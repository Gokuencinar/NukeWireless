# BLE map visibility — diagnostic26

Reference phone, diagnostic25: the user saw active location but no marker. Read-only inspection confirmed 19 history devices, seven with observations, storage_error=0 and 140 BLE callbacks in the latest scan (seven peers). All seven locations had exactly the same coordinates and accuracy about 9.3 m. No actual coordinates, names or UUIDs were copied to the report. This excludes missing permission, a failed fix and absent saved observations in that instance; it does not prove the exact internal MapKit rendering cause.

Diagnostic25 used MapKit automatic annotation clustering for all returned annotation views (including clusters), and fitted the initial viewport to the accuracy circle. Its first rendering fixture covered a single point with 150 m accuracy. Diagnostic26 combines coincident observations in the model into a single counted marker, disables automatic recursive clustering, requires marker display priority, and fits at least a 1 km initial viewport once the map has valid bounds. The fit flag is set before changing the viewport to avoid synchronous layout reentry; appearance retries an unfinished fit without resetting a completed one. The marker remains at the observed phone coordinate; no artificial offsets or transmitter coordinates are introduced. A Show saved locations button explicitly recenters after panning. History, location consent/retention, scan/Stop and privileged radio paths are unchanged.

Adds ble_map diagnostic snapshots: source-device/place counts, visible attached markers, fitted flag, view size, map loading error code and history state. No location coordinates, viewport center, peer identity or announced names enter the diagnostic journal. Fully rendered notification is recorded once while visible; errors are deduplicated.

Pure tests cover seven coincident observations, maximum uncertainty and a distinct place. The UI regression now renders seven coincident peers and includes actual simulator screen capture, required-priority annotation visibility, navigation, rotation and background cycles in English/Spanish on iPhone and iPad. The first candidate passed model checks while its captures were blank; it was rejected before installation. The stronger check requires a rendered frame, a nonhidden marker with nonzero size inside the map and a visible fixture in the actual screen capture. Physical visibility and base-map loading remain subject to acceptance of the new build, not inferred from compile-only evidence.

Reference API: https://developer.apple.com/documentation/mapkit/mkannotationview/clusteringidentifier and https://developer.apple.com/documentation/mapkit/mkannotationview/displaypriority
