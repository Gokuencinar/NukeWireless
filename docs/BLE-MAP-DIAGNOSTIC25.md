# BLE map, proximity and service labels — diagnostic25

Continues diagnostic24, diagnostic23 LAN names and the accepted UART cleanup path. The privileged Bluetooth worker stays diagnostic11, with unchanged radio sources. No new hooks, entitlements or background modes.

Bluetooth → BLE Scanner adds Save detection locations (off by default each screen) and Detection map. CoreLocation is created only after an explicit toggle; the system asks for When In Use permission. Denied/restricted/unavailable location never blocks BLE scanning. Updates run only during the existing foreground 15-second scan and stop on Stop, departure or background. Permission changes resume only the still-running scan. No retrospective assignment to devices without a fresh callback.

A fix must have finite coordinates in range, accuracy 0–5000 m and age at most ten seconds. Approximate location is accepted with its recorded uncertainty. Up to eight observations per UUID, spaced at least ten seconds, are stored in the bounded local history (200 UUIDs, 2 MiB load limit). The map shows the latest observation for each UUID (up to 200 pins/circles, clustering), with date and accuracy circle. These are the iPhone's observation places, never a computed transmitter position. Apple Maps supplies the base map; offline tiles are not guaranteed. No location permission is requested just by opening history or the map. Delete saved locations preserves the other history; Delete history removes everything. Intentional JSON history export includes saved locations; redacted diagnostics contain status/counts only.

Device detail offers Signal / Proximity. The rings visualize RSSI strength with no bearing, coordinates or distance estimate. Live readings older than three seconds become unavailable. Historical views show recorded signal, clearly reached through History. VoiceOver summarizes the same value, translations and dynamic colors are retained.

Recognized advertised services are derived strictly from UUIDs: Device Information 180A, Heart Rate 180D, Battery 180F, HID 1812, Environmental Sensing 181A and Google Fast Pair FE2C. Short and standard expanded UUIDs are normalized. Other values remain unknown; name/company/RSSI never assert police, camera, meter, vehicle or authenticated manufacturer identity. No connections or mesh decoding are introduced.

Sources: https://developer.apple.com/documentation/corelocation/cllocationmanager ; https://developer.apple.com/documentation/mapkit/mkmapview ; https://www.bluetooth.com/specifications/assigned-numbers/ ; https://developers.google.com/nearby/fast-pair/specifications/service/provider

Validation targets: pure location bounds/freshness, persistence and location-only deletion, unknown UUIDs and normalization, scanner/detail Stop, no manager on opening, map annotations, bilingual signal/proximity UI, iPad layouts/rotation and background navigation, package purpose key without location background modes. Native compilation/simulator validation require macOS CI; physical permission, accuracy, tiles and behavior require a device acceptance report. Public UIKit/MapKit/CoreLocation APIs used here predate the existing iOS 15 binary minimum. This does not verify every iOS/hardware combination.
